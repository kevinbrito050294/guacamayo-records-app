===============================================================================
ACCESO AL PANEL - LA PRIMERA VEZ:
===============================================================================

El backoffice se entra con EMAIL + CONTRASEÑA. Cada persona del equipo
tiene su propio usuario en la base de datos.

1) Corré las migraciones pendientes (una sola vez):
   npm run migrar
   → En Railway: shell del servicio MySQL, con la base "railway" seleccionada
   → Los archivos se pueden correr varias veces, no rompen nada
   → OJO: son 4 migraciones, no solo la de cuentas. El checkout escribe
     cupon_id / cupon_codigo / descuento_aplicado y sin esas columnas se cae.
     Arrancando de una base VACÍA, corré primero
     `node scripts/migrar.mjs --archivo 2026-09-29_pedidos_cupones.sql`
     y después `npm run migrar` (ver docs/COUPONS.md)

2) Creá el usuario admin (mínimo 8 caracteres):
   $env:ADMIN_PASSWORD='mi-clave'; node scripts/crear-admin.mjs --email admin@guacamayorecords.com --nombre "Guacamayo"

   Si el email ya existe, el mismo comando cambia la contraseña.

3) Entrá al panel con ese email y esa contraseña.

Detalle completo: README.md → "🔐 Acceso y Cuentas"

STACK TECNOLÓGICO:
================================================================================

Frontend:   React 18 + TypeScript
Estilos:    Tailwind CSS
Backend:    Node + Express (server.js, auth.js) con sesiones y hash scrypt
Base Datos: MariaDB / MySQL en Railway (mysql2)
Build:      Vite 5
Hosting:    Railway (front + API) o tu servidor

Nada complicado. Nada que no entendías.
Todo está listo para producción, con una condición: hay que correr las
migraciones (npm run migrar) y poner tu número de WhatsApp.

RECORDATORIOS:
================================================================================

- El Dólar Blue cambia TODOS LOS DÍAS
  → Actualiza la tasa al menos una vez al día
  → Panel Admin → Tasas de Cambio (1 minuto)

- Los vinilos necesitan buenas imágenes
  → Usa URLs HTTPS (Pexels, Imgur, etc.)
  → No pierdas fotos en el servidor local

- El número de WhatsApp es PÚBLICO
  → Aparece en el código fuente
  → Si no quieres, pídele al dev que lo oculte

- No se comparte la contraseña del admin
  → Cada persona tiene su propio usuario
  → Si alguien se va del equipo, se desactiva su usuario
  → Si se pierde la clave, se resetea con scripts/crear-admin.mjs

- El login con Google necesita DOS variables que tienen que coincidir
  → GOOGLE_CLIENT_ID (server) y VITE_GOOGLE_CLIENT_ID (front), mismo valor exacto
  → Si falta la del front, el botón NO APARECE y no da ningún error
  → Hay que registrar http://localhost:5173 en la consola de Google (en dev)
  → Detalle: README.md → "🔐 Acceso y Cuentas"

- Responde rápido los mensajes de WhatsApp
  → Los clientes esperan confirmación
  → Máximo 1 hora de respuesta
